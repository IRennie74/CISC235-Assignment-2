For each n I made a random list and tried different k values. Half the
targets were in the list and half weren't. A is k linear searches, B is
merge sort + k binary searches (sort time counted in B). Each time was
averaged over 5 trials and I ran the whole thing 3 times.

Table 1 - k* for each run

n       run1  run2  run3  avg
1000    63    59    65    62.3
2000    67    69    64    66.7
5000    73    73    73    73.0
10000   76    77    78    77.0

Table 2 - k*/n

n       avg k*  k*/n
1000    62.3    0.0623
2000    66.7    0.0333
5000    73.0    0.0146
10000   77.0    0.0077

In Table 1, k* only goes up a little as n increases. n went
up 10x but k* only went from about 62 to 77.

So k*/n decreases as n increases (Table 2). It's roughly cut in half
every time n doubles.

This is because a linear search takes about n steps but sorting takes
about n log n, so B starts winning once k is around log n. log n grows
way slower than n, so k*/n keeps getting smaller.
